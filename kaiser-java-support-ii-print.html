2. SQL — VALIDATION & TRIAGE

Workflow: Read-only → count → MAX(timestamp) → duplicates/orphans → locks → EXPLAIN

-- Row count
SELECT COUNT(*) FROM member_eligibility WHERE effective_date = CURRENT_DATE;
-- Duplicates
SELECT member_id, COUNT(*) FROM claims_staging GROUP BY 1 HAVING COUNT(*)>1;
-- Orphans
SELECT c.claim_id FROM claims c LEFT JOIN members m ON c.member_id=m.member_id WHERE m.member_id IS NULL;
-- Stale feed
SELECT source_system, MAX(last_updated_ts) FROM eligibility_feed GROUP BY 1;
-- Blocking (PostgreSQL)
SELECT pid, NOW()-query_start AS dur, LEFT(query,120) FROM pg_stat_activity WHERE state!='idle' ORDER BY dur DESC;
-- Latest plan per member (LATERAL)
SELECT m.member_id, e.plan_code FROM members m JOIN LATERAL (
  SELECT plan_code FROM member_eligibility e WHERE e.member_id=m.member_id
  ORDER BY effective_date DESC LIMIT 1) e ON TRUE;

3. KAFKA — LAG TRIAGE

30-sec answer: Producers → partitioned topics → consumer groups read offsets. Lag = log end − current offset.

kafka-consumer-groups.sh --bootstrap-server <broker>:9092 \
  --group eligibility-consumer-prod --describe
kafka-topics.sh --bootstrap-server <broker>:9092 --describe --topic patient-eligibility-events
SignalCauseAction
Lag all partitionsSlow consumerThread dump; DB; scale ≤ partitions
Lag one partitionHot keyIdentify skewed member_id
Rebalance loop> max.poll.intervalFaster handler; smaller batch
Poison pillBad message retriesDLT; skip; replay offset

Healthcare: No PHI in logs; partition key = member_id; lag = stale eligibility = member impact

4. SPLUNK — SPL TEMPLATES

Fields: index, sourcetype, level, correlationId, exception, host

-- Error spike
index=kp_apps level=ERROR earliest=-1h | timechart span=5m count
-- Top exceptions
index=kp_apps earliest=-30m | rex field=_raw "(?<ex>[a-zA-Z0-9_.]+Exception)"
| stats count by ex | sort - count
-- Trace request
index=kp_apps correlationId="<id>" earliest=-24h | sort _time | table _time host level message
-- JDBC pool
index=kp_apps earliest=-2h ("CannotGetJdbcConnection" OR "HikariPool" OR "SQLTimeout")
| stats count by host, message
-- Kafka issues
index=kp_apps earliest=-2h ("rebalance" OR "offset commit" OR "org.apache.kafka")
| stats count by message
-- Deploy correlation
index=kp_deployments OR index=kp_apps earliest=-4h | sort _time
-- Alert
index=kp_apps level=ERROR earliest=-5m | stats count as c | where c > 50
